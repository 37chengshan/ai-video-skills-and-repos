# AI 视频制作 Skill 教程

> 写给第一次用 AI 做视频的人，也写给要执行任务的 AI agent。
>
> 目标：读完能装好环境、选对工具、做出第一支 30–60 秒概念片，并知道 90–180 秒音乐 MV 该怎么开工。
>
> 不假设你已经有任何项目、任何代码、任何素材。

```text
你是视频制作 agent。先不要写代码，按这个顺序做：

```

## 0. 先读这一页

### 0.1 你会得到什么

- 一套从空电脑开始的环境检查清单。
- 六个公开仓库/工具：各自是什么、能做什么、怎么装、怎么用。
- 音乐概念 MV 的三条路线和一套 10 步流程。
- 知识片、产品片、历史片、竖屏片等赛道的工具选择。
- 哪些工具必须组合、哪些不能混、哪些其实不能直接用。

### 0.2 你需要准备什么

| 需要 | 说明 |
|---|---|
| 一台电脑 | macOS 最省事；Windows 建议用 WSL；Linux 也可以 |
| 网络 | 下载 Node、Chrome、FFmpeg、仓库依赖 |
| 一个 AI agent | Claude Code、Codex、Cursor 等，能读文件、能执行命令即可 |
| 可选：图像 API | 需要生成封面/角色图时；没有也能用代码画面 |
| 可选：音乐 | 自己的歌、已授权曲库，或让工具生成配乐 |

### 0.3 先懂这几个词

| 词 | 人话解释 |
|---|---|
| **Agent** | 能读文件、写代码、执行命令的 AI 助手。Claude Code、Codex、Cursor 都算。 |
| **Prompt** | 你写给 agent 的指令/问题；越具体，结果越稳。 |
| **Skill** | 一个文件夹，里面有 `SKILL.md`，告诉 agent「这类任务按什么步骤做」。装进 agent 的技能目录后，agent 就能调用。 |
| **Runtime（运行时）** | 真正把画面渲染成视频的引擎。huashu 用 Chrome 截帧；Lemo 用 Chrome + FFmpeg；PDoom 用 p5 + Chrome + FFmpeg。 |
| **工程模板** | 一套可以读、可以改的源码工程，不是 skill。你要自己改代码，不能一句命令出片。 |

再懂这些词：

| 词 | 人话解释 |
|---|---|
| **Treatment** | 一页纸的导演方案：讲什么、什么结构、什么镜头、什么声音。 |
| **Storyboard（分镜）** | 每个镜头画什么、多长时间、怎么转场。 |
| **Beat map / Cue sheet** | 音乐的时间表：第几秒是重拍、哪里进副歌、哪里停。 |
| **BPM** | 每分钟拍数。120 BPM = 每拍 0.5 秒。 |
| **LUFS** | 响度单位。视频平台一般要求整体约 −14 到 −11 LUFS，真峰值不超过 −1 dB。 |
| **TTS** | 文字转语音：把稿子变成配音。 |
| **ASR** | 语音转文字：把录音变成字幕。 |
| **stems** | 分轨：人声、鼓、贝斯、旋律分开的文件。 |
| **foley** | 拟音：脚步、开门、纸张等动作音效。 |
| **LUT** | 调色预设：统一画面颜色的文件。 |
| **SRT** | 字幕文件格式。 |
| **loop** | 循环片段：最后一帧接回第一帧。 |

### 0.4 三个概念别搞混

| 类型 | 例子 | 能不能直接出片 |
|---|---|---|
| Skill | huashu-motion、lemo-opuscar、short-video-script | 能（short-video-script 只出文案） |
| 工程模板 | PDoomVideo | 不能，要自己改代码 |
| 语料库 | awesome-opus5-5-videos、opus-video-prompts | 不能，只能查 prompt/案例 |

**这是新手最容易踩的坑**：把语料库当工具、把工程模板当 skill，结果折腾半天出不了片。

### 0.5 一页总表

| 名字 | 是什么 | 最适合 | 安装方式 | 难度 | 许可 |
|---|---|---|---|---|---|
| **huashu-motion** | 成片 skill | 30–60 秒概念片、产品片、动态图形、loop | `npx skills add` | 中 | MIT（角色除外） |
| **lemo-opuscar** | 成片 skill + 59 种风格库 | 30–90 秒风格短片、城市/历史/产品/纪实 | Claude 插件市场或克隆 | 中高 | 代码 MIT；样片 CC BY 4.0 |
| **PDoomVideo** | 工程模板 | 90–180 秒手绘/水彩 MV | `git clone` + `npm install` | 高 | 无 LICENSE，只学方法 |
| **awesome-opus5-5-videos** | 语料库 | 找 prompt、技术路线、MV/音频案例 | `git clone` | 低 | MIT（prompt/视频归原作者） |
| **opus-video-prompts** | 语料库 + 教程 | 学六段式 prompt、Remotion 规则、长片/TTS | `git clone` | 低 | 无 LICENSE，只学方法 |

## 1. 环境准备

### 1.1 装什么

| 组件 | 版本 | 用途 | 检查命令 |
|---|---|---|---|
| Node.js | **≥ 22** | 所有 JS 工具、huashu、Remotion | `node -v` |
| npm | 随 Node | 安装依赖 | `npm -v` |
| Chrome / Chromium / Edge | 最新版 | 逐帧截屏、huashu 编辑器、Remotion | 打开 `chrome://gpu` 能看 |
| FFmpeg | ≥ 6 | 编码、混音、响度、抽帧 | `ffmpeg -version` |
| Python | ≥ 3.11，或 `uv` | 音频分析、部分脚本 | `python3 -V` 或 `uv --version` |
| Git | 任意 | 克隆仓库 | `git --version` |

### 1.2 一条条检查

```sh
node -v            # 期望 v22.x 或更高
npm -v
ffmpeg -version    # 期望有版本号
python3 -V         # 期望 3.11+
git --version
```

如果 `ffmpeg` 没有：

```sh
# macOS
brew install ffmpeg

# Ubuntu / Debian
sudo apt install ffmpeg
```

如果 Node 太旧：

```sh
# macOS
brew install node@22

# 或者用 nvm
nvm install 22
nvm use 22
```

### 1.3 给 agent 的一段话

把下面这段交给你的 agent：

```text
你是视频制作 agent。先检查环境：
1) node -v 是否 >= 22
2) ffmpeg -version 是否有输出
3) Chrome 是否安装
4) python3 -V 是否 >= 3.11，或 uv --version
缺什么就告诉我怎么装，不要直接开始写视频。
```

### 1.4 内存设置

渲染视频容易吃内存。所有 `npm` / `npx` / `node` 命令前，建议先执行：

```sh
export NODE_OPTIONS=--max-old-space-size=4096
```

Windows PowerShell：

```powershell
$env:NODE_OPTIONS="--max-old-space-size=4096"
```

### 1.5 常见环境问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `npm install` 被 OOM 杀 | Node 默认内存不够 | 设置 `NODE_OPTIONS` |
| Remotion 找不到 Chrome | 没装浏览器/路径不对 | `npx remotion browser ensure` |
| `ffmpeg: command not found` | 没装 | `brew install ffmpeg` / `apt install ffmpeg` |
| `uv: command not found` | 没装 | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |
| 中文变方块 | 缺中文字体 | macOS 用宋体/苹方；Linux 装 Noto Sans CJK |
| 渲染很慢/黑屏 | 没有 GPU 或浏览器没开硬件加速 | 用真实 Chrome；不要在没有 WebGL 的服务器上跑 p5/Three.js |

## 2. 六个仓库怎么选

### 2.1 先看你想做什么

| 你想做 | 先看 | 为什么 |
|---|---|---|
| 30–60 秒概念片/产品片 | **huashu-motion** | 一个 skill 从方向到成片，自带编辑器和配乐 |
| 30–90 秒有电影感的风格短片 | **lemo-opuscar** | 59 种 `STYLE.md` + 导演手册 |
| 90–180 秒手绘/水彩 MV | **PDoomVideo** | 完整的 MV 工程模板，含分镜/时间轴/水彩渲染 |
| 找参考、找 prompt、找技术路线 | **awesome / opus-video-prompts** | 语料库，不是工具 |
| 先写标题/钩子/口播/分镜 | **short-video-script-skill** | 纯提示词，出文案，不出画面 |

### 2.2 六个仓库分别是什么

#### huashu-motion

- 一个 skill。你把一句话交给 agent，它先给你 3 个方向，再写代码、写谱、渲染。
- 画面是 HTML + GSAP/Canvas/SVG/Three.js，浏览器逐帧截屏。
- 有一个浏览器编辑器，你可以指着某一帧说「这里改一下」。
- 适合：产品发布、动态图形、解说、UI loop、30–60 秒概念片。
- 不适合：已有完整歌曲、要逐句歌词叙事的长 MV。

#### lemo-opuscar

- 一个 skill + 59 个风格目录。
- 每个风格有一份 `STYLE.md`（这个风格是什么、颜色、字体、运动、声音、镜头、坑），还有一支用代码做的 demo。
- `DIRECTOR.md` 教你怎么导：brief → benchmark → story → treatment → 分镜 → 生产 → 审片。
- 适合：30–90 秒风格短片、城市交响、视觉调查、水彩/油画/浮世绘/皮影/剪纸、产品拆解。
- 不适合：想要一键出 2 分钟歌词 MV 的新手。

#### PDoomVideo

- 一个 156.6 秒水彩 MV 的完整源码工程，不是 skill。
- 9 章、62 镜、纯函数时间轴、p5 + p5.brush + Chrome + FFmpeg。
- 适合：想研究「长 MV 怎么组织代码」的人；想改成自己的歌的人。
- **注意**：仓库没有 LICENSE 文件，默认保留所有权利；只能学方法，不能直接抄代码。歌曲、歌词、角色也不能复用。

#### awesome-opus5-5-videos

- 703 条 prompt + 418 条 live remake 链接。
- 不是工具，是语料库。你可以按分类、技术标签、关键词检索。
- 适合：找「别人怎么写 prompt」、找技术路线、找 MV/音频案例。
- **注意**：MIT 只覆盖仓库代码/文档；每条 prompt 和视频归原作者，不能整段转载或当自己的作品。

#### opus-video-prompts

- 18 份完整 prompt、54 个公开案例、9 条技术路线。
- 教程式语料库：教你六段式 prompt、Remotion 工程规则、长片/TTS 经验。
- 适合：想学「怎么写一个能交付的 prompt」。
- **注意**：没有 LICENSE 文件；只学方法/结构，不要整段复制。

#### short-video-script-skill

- 纯提示词 skill。输入主题/文章/论文，输出 8 个标题、5 个钩子、口播稿、分镜、封面文案、发布文案。
- 不渲染、不合成、不需要 API key。
- 适合：任何赛道的「文案与分镜」阶段。
- **注意**：`SKILL.md` 声称 MIT，但仓库没有 LICENSE 文件；对外分发前先联系作者。

### 2.3 一张决策图

```text
你要做什么？
├─ 音乐 MV
│  ├─ 有歌，要手绘/水彩叙事 → PDoomVideo（工程模板）
│  ├─ 有歌，要实拍/城市 → lemo-opuscar 的 city-symphony
│  └─ 没歌，要 30–60s → huashu-motion
├─ 知识科普
│  ├─ 30–60s 通用 → huashu-motion（3b1b / kurzgesagt 语法）
│  └─ 30–90s 电影感 → lemo-opuscar
├─ 产品/品牌 → huashu-motion
├─ 历史/纪录 → lemo-opuscar
├─ 竖屏/短视频 → huashu-motion（kinetic-type / loop）
└─ 只要标题/钩子/分镜 → short-video-script-skill
```

## 3. 逐个上手

### 3.1 huashu-motion：从一句话到 30 秒片

#### 安装

```sh
npx skills add alchaincyf/huashu-motion
```

`npx skills add` 是 Agent Skills（一种通用的 skill 安装格式）的安装器，会把 skill 放进当前 agent 的技能目录。

`om` 是 huashu 的命令行工具，负责新建项目、预览、检查、渲染。

如果你的 agent 不认 `npx skills add`，手动装：

```sh
git clone https://github.com/alchaincyf/huashu-motion.git ~/huashu-motion
ln -s ~/huashu-motion/skills/huashu-motion ~/.claude/skills/huashu-motion
```

Codex 用户把 `~/.claude/skills` 换成 `~/.codex/skills`；其他 agent 换到它自己的 skills 目录。

#### 验证

```sh
~/huashu-motion/skills/huashu-motion/bin/om doctor
```

如果用的是 `npx skills add` 安装，直接：

```sh
npx huashu-motion doctor
```

它应该检查 Node、Chrome、FFmpeg 三项。缺什么就装什么。

> 下面的命令用 clone 安装的路径举例。如果你用 `npx skills add` 安装、没有 `~/huashu-motion`，把命令里的 `$OM` 换成 `npx huashu-motion`，或先按上面的方式 clone 一份。

#### 第一支 30 秒片

先建一个项目：

```sh
OM=~/huashu-motion/skills/huashu-motion/bin/om
$OM new my-first-film --template kinetic-type
```

打开编辑器：

```sh
$OM studio my-first-film --no-open
```

它会打印一个本地网址（通常是 `http://127.0.0.1:...`）。打开后可以预览、拖动、在画面上留言。

先出一帧看看：

```sh
$OM still my-first-film --at 1.2
```

渲染：

```sh
$OM render my-first-film
```

产物在 `my-first-film/out/`，文件名类似 `my-first-film-v1.mp4`。

#### 给 agent 的启动提示词

```text
用 huashu-motion 做一支 30 秒、16:9 的概念片，主题是「一个人在城市里寻找安静」。
先给我 3 个方向，每个方向 1 张真关键帧 + 1 张卡片（运动语言、节奏、颜色、声音各一句）。
不要直接开做。我选一个后，你再写 treatment、先做最难镜头、om sound 写谱、om check、om qa、om render。
```

#### 它能做什么

- 30–60 秒概念片、产品发布、动态图形、解说、UI loop、GIF。
- 20 个运动语言、8 个语法模板、12 个起步模板。
- 23 种音效；16 个音乐世界；12 类产品 × 3 个兜底配乐方向。
- 浏览器编辑器：指着画面改，agent 只改那一处。
- 输出 MP4、MOV（透明）、WebM、GIF、分享页。

#### 它不能做什么

- 不能拿你的歌当主轨并自动卡点。官方流程是它自己写谱；要用现成歌，需要手动替换音频或加 `<audio>`。
- 不会生成真人/实拍；真人素材要你自己提供。
- 听不见声音；只能靠频谱/能量曲线检查，最后必须人耳听。
- 不自动发布。

#### 许可

MIT；但「豆子花叔」角色不随 MIT 授权；GSAP 是 GSAP Standard License；字体是 OFL。你做出来的片子归你。

### 3.2 lemo-opuscar：59 种风格，先选风格再讲故事

#### 安装

**方式一：Claude Code 插件市场**

```sh
claude plugin marketplace add lemomo-ai/lemo-opuscar
claude plugin install lemo-opuscar@lemolab
```

**方式二：克隆**

```sh
git clone https://github.com/lemomo-ai/lemo-opuscar.git ~/lemo-opuscar
cd ~/lemo-opuscar
```

**方式三：复制 skill 目录**

把 `plugin/skills/lemo-opuscar/` 复制到你的 agent skills 目录。

#### 验证

> 如果你用 Claude 插件市场安装，首次调用 skill 时会自动运行 setup，不需要手动跑下面的命令；下面的路径是 clone 安装的。

```sh
sh ~/lemo-opuscar/plugin/skills/lemo-opuscar/scripts/setup.sh
```

最后一行应该打印 `LIB=<路径>`。第一次会下载风格库和依赖，约 350MB；voice/music 依赖按需再装。

#### 第一支 30–60 秒片

先看风格列表：

```sh
cat ~/lemo-opuscar/styles/README.md
```

选一个风格（例如 `watercolor`、`city-symphony`、`swiss-motion`、`dark-keynote`），然后给 agent：

```text
用 lemo-opuscar 的 watercolor 风格，做一支 45 秒、16:9 的短片。
主题：<一句话>。
先写 TREATMENT.md：3 个候选结构 → 选 1、benchmark、shot list、beat sheet、cue map、声音表。
再给我 3 张风格帧；不要直接写整片。
```

它会：

1. 读 `STYLE.md`（这个风格的固定规则）。
2. 写 `TREATMENT.md`（导演方案）。
3. 用真实绘图代码渲 3 张风格帧。
4. 你确认后，做动画、配音/配乐、混音、渲染。
5. 输出 mp4 + poster + srt + TREATMENT + CREDITS + build.sh。

#### 它最值钱的地方

- 59 种风格不是 59 个模板，而是 59 份「语法」：颜色、字体、运动、镜头、声音、坑。
- `DIRECTOR.md` 的判片顺序：**声音 → 节奏 → 镜头 → 导演**。
- 先写 treatment，再打开 demo；不允许照抄 demo 的故事/镜头/时间码。
- 至少两次真静音、两次声音转场、一轮修复。
- 字幕停留有公式：中文 ≈ 字数÷4.5+1.5 秒，英文 ≈ 字母÷15+1.5 秒。

#### 它不能做什么

- 不是一键 MV 工具；默认 30–60 秒，90 秒以上要显式加成本。
- `city-symphony` 需要真实素材（延时/航拍/档案），不是纯代码。
- 需要 GPU 的风格（3D/着色器）在没有 GPU 的机器上很慢或跑不动。
- 样片和 demo 素材不能当自己的作品发；代码 MIT，样片 CC BY 4.0（要署名）。

#### 许可

代码/文档 MIT；demo 影片/剧照 CC BY 4.0（署名 LemoLab + 链接 + 注明改动）；三条配音轨不授权；第三方素材各自许可。你做的片子归你。

### 3.3 PDoomVideo：研究 156 秒 MV 工程

#### 安装

```sh
git clone https://github.com/JohnHeibel/PDoomVideo.git
cd PDoomVideo
npm install
```

它需要 Node、Chrome、FFmpeg。macOS/Linux 要指定 Chrome 路径：

```sh
node render.mjs --chrome="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --stills=39.5 --out=out/check
```

#### 先出几张静帧

```sh
node render.mjs --stills=39.5,43.2 --out=out/check
```

看 `out/check/` 里的 JPG。日志会打印每帧耗时（ms/frame）。

#### 渲染整片

```sh
node render.mjs --frames=0:156.6 --workers=4
node render.mjs --encode --out=out/pdoom.mp4
```

`--frames` 是断点续渲：已经渲过的帧会跳过；`--encode` 把帧和歌合成 MP4。

#### 怎么改成你的歌

1. 把歌放到 `assets/`，改 `render.mjs` 里的音频路径。
2. 改 `src/core.js` 的 `BPM`、`OFF`（第一拍偏移）、`DUR`。
3. 改 `src/lyrics.js` 的歌词时间表（`[start, end, text]`）。
4. 改 `STORYBOARD.md`：每镜 `Time / Lyric / Shot / Out`。
5. 改 `ANIMATION_GUIDE.md` 的契约（如果多人/多 agent 并行）。
6. 改 `src/ch/c01..c09` 的章节；一章一个文件。
7. 每章用 `--sheet` 出接触表，检查动作读不读得出。
8. 整片 `--frames --workers=4` → `--encode`。

#### 工程契约（最值得学）

- 每个镜头是 `fn(t, lt, dur)`，必须画满整帧，包括背景。
- 每一帧都是 `t` 的纯函数；不能有跨帧状态；不能用 `Math.random()`。
- 稳定随机用 `hash(i)`；手绘抖动用 `jit(a)`（12fps 沸腾）。
- 字幕带在 y≈975–1070；关键动作/脸在 y<960。
- 性能目标 ≤2.5 秒/帧，绝不超 4 秒。
- 章节边界用「动作跨切」，不是每章淡出。

#### 许可警告

**仓库没有 LICENSE 文件**；`package.json` 里的 `"license": "ISC"` 是 npm 模板残留，不足以构成授权。默认保留所有权利。

- 可以学：纯函数时间轴、`chapter()` 注册、`bpOf/pulse`、水彩纸纹、断点续渲、`--sheet` 自检。
- 不可以抄：代码、Clawd 角色、62 镜具体构图、歌曲、歌词。
- 你自己的 MV 要重写实现。

### 3.5 opus-video-prompts：18 份 prompt 和六段式骨架

#### 使用

```sh
git clone https://github.com/joeseesun/opus-video-prompts.git
cd opus-video-prompts
```

先读：

- `prompts/15-ui-morph-loop.md`：UI 形态变换循环，六段式骨架。

- `prompts/11-austerlitz-film.md`：4–5 分钟历史长片。
- `prompts/09-atmospheric-circulation-tts.md`：TTS 科普。

#### 六段式骨架

```text
<inputs>
先问我要：主体/品牌、3–5 个瞬间、一个主色、真实素材、BPM 明确的曲子。
If I skip anything: 用默认值……
</inputs>

<direction>
一句定位 + 三个否定；一个主色；一种字体。
Banned: 粒子爆发、镜头光晕、RGB 分离、霓虹辉光、弹跳缓动、UI chrome 上加渐变/发光。
</direction>

<structure>
120 BPM，32 beats（16s）。Beats 0-6 …；Beat 6 …；Beat 12 the drop …。
每拍一个动作，不写「流畅/高级」。
</structure>

<build>
1. 交付形态 + 尺寸 + 帧率。
2. 每帧是时间的纯函数（seek(t)），无 CSS 动画、无计时器、无跨帧状态。
3. 弹簧闭合解；目标多次变化时按次叠加。
4. 音频：分析 tempo/beat grid/drop；切点落 downbeat；音效按 measured peak；loudnorm −14 LUFS。
5. 渲染：3–4 subframes + tmix；真实素材抽 30fps JPEG 序列。
6. 预检：每拍渲一帧；至少 20 帧；再全片。
</build>

<gotchas>
will-change 不要加在被相机缩放的层；preserve-3d 上别设 opacity/filter；
morph 容器里的文字要独立进出；末帧 = 首帧（含光标速度）；
没有商用授权音频就交无声母版 + cue sheet。
</gotchas>

<start>
先给我 beat map + 4 张关键静帧，确认后再写整片。
</start>
```

#### 必须先纠正的三个事实

1. **12/13 是 Remotion**：标签和说明是 Remotion，但**正文 prompt 里没有 "Remotion"**；正文是工具无关的「先 storyboard 再写代码」。
2. **15/16 不是 Remotion**：`<build>` 第 1 条写 `One HTML file`；管线是 Playwright（浏览器自动化）截帧 + ffmpeg `tmix`（运动模糊滤镜）。规则可以迁移，但技术栈不是 Remotion。
3. **`<start>` 是门禁**：没有它，模型会直接开写代码；有它，先交 beat map/storyboard。

#### 许可

无 LICENSE 文件；只学方法/结构，不要整段复制、不要搬案例素材。

## 4. 音乐概念 MV 教程

### 4.1 什么是概念 MV

**概念 MV**：音乐是脚本，画面是音乐的可视化叙事；没有口播；一个视觉母题贯穿；30–180 秒；观众听完歌，记住一个画面。

**不是什么**：

- 不是「给知识片配一首歌」：知识片的结构是论证，MV 的结构是音乐。
- 不是「歌词字幕 + 风景空镜」：那是卡拉 OK / 旅行视频。
- 不是「表演 MV」：除非你明确要拍人声表演。
- 不是「十个炫技镜头合集」：没有母题，观众记不住。

### 4.2 三条路线

```text
你有已经完成的歌吗？
├─ 有
│  ├─ 想要真人/实拍/档案素材？
│  │  ├─ 是 → lemo-opuscar 的 city-symphony / visual-investigation
│  │  └─ 否
│  │     ├─ 想要手绘/水彩/绘本叙事？→ PDoomVideo 工程模板
│  │     └─ 想要图形/抽象/UI/3D？→ huashu-motion
└─ 没有
   └─ 想要它自己写谱？→ huashu-motion 作曲家模式
```

| 路线 | 工具 | 时长 | 你要会什么 | 产出 |
|---|---|---|---|---|
| A | PDoomVideo | 90–180s | 基本 JS、愿意改代码 | 水彩/手绘 MV |
| B | lemo-opuscar `city-symphony` | 30–90s | 会找素材/授权 | 实拍/城市/档案 MV |
| C | huashu-motion | 30–60s | 会写一句话/给参考 | 概念/图形 MV |

### 4.3 十步流程

| 步 | 做什么 | 产物 |
|---|---|---|
| 0 | 定曲/授权/时长/画幅 | 授权清单、`track.md` |
| 1 | 拆歌 | BPM、段落、drop、歌词表、cue sheet |
| 2 | 写概念 | logline、视觉母题、颜色脚本、结尾 |
| 3 | 选路线/风格 | 路线 A/B/C + 主风格 + 辅助手法 |
| 4 | 写 treatment | 3 个候选结构 → 选 1；镜头表；cue map；声音表 |
| 5 | 写分镜 | `STORYBOARD.md`：Time / Lyric / Shot / Out |
| 6 | 5 秒测试 | 3–5 张关键帧 + 5 秒样片 |
| 7 | 建工程/资产 | 工程、素材、字体、颜色 |
| 8 | 先做最难镜头 | 一个完整镜头，全分辨率 |
| 9 | 铺满 | 全部镜头；一章一个文件/agent |
| 10 | 声音/QA/交付 | 混音、MP4、SRT、封面、授权清单 |

### 4.4 第一步：定曲与授权

优先级：

1. 原创/委托创作：版权最清楚，可以拿到 stems。
2. 已授权曲库：确认平台、期限、地域、商业化、二次剪辑、Content ID。
3. 用户确认有授权的曲子。
4. 不做：从抖音/B站/YouTube/别人的视频里提取 BGM。

需要拿到：

- 音频文件：WAV 或高质量 MP3。
- BPM、拍号、时长。
- 段落标记：intro / verse / chorus / bridge / outro。
- 重拍/停顿/硬切点。
- stems（人声、鼓、贝斯、旋律、氛围）如果可用。
- 授权范围：平台、地域、期限、商业化、改编、署名。
- 是否注册 Content ID。

没有授权音频时：**交无声母版 + cue sheet**，不要从网上抓歌。

### 4.5 第二步：拆歌

工具：Audition、Logic、Ableton、Sonic Visualiser，或任何 BPM 检测工具。自动检测后要手动核对，防止半速/双速。

要标：

| 项目 | 说明 |
|---|---|
| 起始偏移 | 第 1 拍在第几秒 |
| BPM | 脚打拍子核对 |
| 拍号 | 4/4、3/4、6/8 |
| 小节 | 每小节几拍；重拍在第几拍 |
| 段落 | intro / verse / build / drop / breakdown / final / outro |
| 能量 | 低/中/高；哪里上升、下降、停顿 |
| 硬切点 | 停顿、reverse cymbal、impact、silence |
| 结尾 | 渐弱、硬停、回到主和弦、loop 点 |

**Cue sheet 模板**：

```markdown
| 时间 | 小节 | 拍 | 段落 | 能量 | 音乐事件 | 画面事件 |
|---|---|---|---|---|---|---|
| 0:00 | 1 | 1 | intro | 低 | 环境垫 | 一个物体在黑暗里 |
| 0:08 | 5 | 1 | intro | 低 | 鼓点进入 | 物体开始发光 |
| 0:16 | 9 | 1 | build | 中 | 贝斯进入 | 镜头开始推进 |
| 0:32 | 17 | 1 | drop | 高 | 重拍 | 主体炸开 / 硬切 |
```

规则：

- 先标「必须发生」的 5–8 个音乐事件，再填画面。
- 音乐稀疏 → 长镜头；音乐密 → 短镜头。
- **歌词表是 MV 的骨架**：一句歌词 ≈ 一镜；镜起点优先跟歌词起点，而不是整拍。
- **镜内击打跟整拍**：泵、砸门、脚步、灯亮，用拍网格。
- 段落边界允许 ±半拍；不要为了卡整拍把歌词切碎。

### 4.6 第三步：写概念

一句话 logline：

> 这支 MV 用 [视觉母题] 经历 [音乐情绪/概念]，最后回到 [开头画面]，但 [变化]。

例：

- 用「一座城市的一天」经历「从秩序到失控再回到秩序」。
- 用「一扇门的光」经历「从黑暗到打开」。
- 用「一个不断变大的物体」经历「从可爱到压迫」。

3–5 个母题：

| 母题 | 视觉规则 | 出现位置 |
|---|---|---|
| 门 | 每扇门一根光柱 | 开头、转折、结尾 |
| 光 | 青 = 安全，红 = 危险 | 全片 |
| 表盘 | 每拍点亮一格 | 回落段 |
| 手 | 只在关键句出现 | 副歌 |

颜色脚本：

- 4–6 个颜色，一个主色，一个强调色。
- 颜色要有语义，不要只是「好看」。
- 开头和结尾用同一组颜色，但强调色可以换。

### 4.7 第四步：写 treatment

一页纸，至少包含：

1. **3 个候选结构**（几行一个），选 1 个并说明为什么。
2. **Logline + arc**：一句，然后 setup → turn → ending。
3. **Benchmark**：学什么 / 不学什么。
4. **Shot list**：每个镜头景别、角度、相机运动、时长、为什么。
5. **Beat sheet**：逐秒。
6. **Cue map**：tempo、bar grid、每段配器、每个切点/动作落在哪拍。
7. **Sound design table**：每段环境、foley、音乐状态。
8. **字幕/标题设计**：字体是风格的一部分。

**结尾**：回到开头画面，但有一个变量变了；不要用「淡出 + logo」。

### 4.8 第五步：写分镜

表头：

```markdown
| Time | Lyric | Shot | Out |
|---|---|---|---|
```

- `Shot` 写「画面里发生的那一件事」，用动词，不写参数。
- `Out` 写「出场方式 / 下一镜的接口」：动作跨切、遮罩、颜色承接、声音 J-cut。
- 每章标题带调色板注释：`## 1 · The Lab (1.5–23) · night indigo, lamp ochre, monitor teal`。

通用规则：

- 一个镜头只发生一件事。
- 切点优先落在拍/细分拍；不要每刀都卡重拍。
- 重拍 → 硬切/闪光/主体变化/颜色反转。
- 停顿 → 静止/黑场/留白。
- 结尾 → 回到开头构图，但变量变了。
- 文字克制：只留标题、数字、出处、一句公版文本。
- 不要下三分之一人名、页眉、居中标题卡翻页、logo sting。

**8 镜示例（16 秒 intro，120 BPM）**：

| # | 时间 | 拍 | 音乐 | 画面 | 镜头 |
|---|---|---|---|---|---|
| 1 | 0:00 | 1 | 环境垫 | 黑暗里一个物体 | 固定 |
| 2 | 0:02 | 5 | 低频进入 | 物体表面亮起一条线 | 慢推 |
| 3 | 0:04 | 9 | 鼓点 | 线扩展成轮廓 | 侧移 |
| 4 | 0:06 | 13 | 鼓点加强 | 轮廓变成门 | 推近 |
| 5 | 0:08 | 17 | 贝斯 | 门开一条缝 | 固定 |
| 6 | 0:10 | 21 | 上升音 | 光从缝里出来 | 拉远 |
| 7 | 0:12 | 25 | 停顿 | 全黑，只有光 | 静止 |
| 8 | 0:14 | 29 | 重拍 | 门全开，光爆 | 硬切 |

### 4.9 第六步：选工具

| 你的情况 | 用 | 为什么 |
|---|---|---|
| 有歌、要水彩/手绘叙事 | PDoomVideo | 完整的 MV 工程模板；纯函数时间轴；水彩管线 |
| 有歌、要实拍/城市/档案 | lemo-opuscar `city-symphony` | 学会把音乐当脚本；切点表、硬停、brake |
| 没歌、要 30–60 秒 | huashu-motion | 一个 skill 从方向到成片；自带写谱/音效/编辑器 |
| 有歌、要图形/UI/抽象 | huashu-motion | 20 个运动语言；可手动接歌 |
| 只要文案/分镜 | short-video-script | 8 标题/5 钩子/口播/分镜 |

### 4.10 给 agent 的提示词

#### 有歌 + 水彩叙事（PDoom）

```text
你是有经验的 MV 导演 + 创意编程工程师。
我的歌：<文件路径>，BPM <n>，第一拍 <s> 秒，时长 <t> 秒，授权：<说明>。
我想做一支 2 分钟、16:9 的水彩概念 MV，主题是 <...>，视觉母题是 <...>。
不要复用任何现成 IP/角色/歌词/旋律。
先写 TREATMENT.md（3 个结构 → 选 1、benchmark、shot list、cue map、声音表），
再写 STORYBOARD.md（Time / Lyric / Shot / Out，每镜一个动词），
先做 8 张关键帧给我看，不要直接写整片。
```

#### 有歌 + 实拍/城市（Lemo）

```text
用 lemo-opuscar 的 city-symphony 风格，做一支 60 秒、16:9 的城市概念 MV。
城市：<...>；情绪：<...>；我有的素材：<...>；没有的你去 Wikimedia/NASA 找，逐条写许可。
先写 TREATMENT.md（benchmark、shot list、beat sheet、cue map、声音表），
再给我 6–9 张关键帧；不要 pop track 旅行片语法。
```

#### 没歌 + 30–60 秒（huashu）

```text
用 huashu-motion 做一支 45 秒、16:9 的概念片，主题是 <...>。
先给我 3 个方向，每个 1 张真关键帧 + 1 张卡片（运动语言、节奏、颜色、声音各一句）。
我选一个后，你写 treatment、先做最难镜头、om sound 写谱、om check、om qa、om render。
不要产品发布片；要音乐性的视觉片，少字幕，一个母题贯穿。
```

### 4.11 QA

- 音乐和画面同步（±2 帧）。
- 每个镜头只发生一件事。
- 没有无意义的运镜。
- 文字可读、不压主体、不折行。
- 开头 3 秒有钩子；第 0 帧有主体。
- 结尾回到母题，有变化。
- 没有黑帧/空镜超过 2 秒（除非设计）。
- 响度达标，真峰值 ≤ −1 dB。
- 没有版权素材/水印/品牌 Logo。
- 字幕/歌词准确。
- 首尾帧可 loop（如果做 loop）。
- 授权清单完整。

### 4.12 常见坑

- **cliché**：蓝色粒子组成大脑、空场一个点呼吸、整屏黑白翻转、粒子爆炸、镜头光晕、RGB 分离。
- **house style**：暖白/近黑底 + 橙红或柠檬绿 + 巨型无衬线 + 等宽小标签 + 一秒模块。选完语言写一句「本片和这个 pattern 差在哪」。
- **35 风格不是 huashu-motion 自带**：它们在另一个项目 `huashu-art-motion`，需要单独安装；不能直接用 huashu-motion 跑。
- **唱词对齐未验证**：huashu 的 `om voice --audio` 是为说话设计的；唱段更稳是手写 cue 表。
- **版权**：音乐只能自己合成/采样（CC0/CC-BY）或用户自带；不要抓商业曲。

## 5. 其他风格赛道

### 5.1 知识科普（无口播）

- **工具**：huashu（`t1_3b1b` 机制、`y1_kurzgesagt` 尺度、`t3_finance_chart` 数据）；Lemo（`swiss-motion`、`dataviz`）。
- **流程**：查一手资料 → 写 3 个候选结构 → treatment → 分镜 → 5 秒测试 → 全片 → QA。
- **示例 prompt**：

```text
用 huashu-motion 做一支 45 秒、16:9 的科普片，解释「为什么飞机能飞」。
用 3b1b 语法：黑底、一次一个概念、用形变把 A 变成 B。
先给我 3 个方向，每个 1 张关键帧；不要直接开做。
```

### 5.2 知识口播

- **工具**：huashu `talking-head` 模板；或任何支持 TTS/ASR 的成片工具。
- **流程**：写口播稿（短句、≤22 字/句）→ TTS/真人录音 → ASR 出 SRT → 画面 → 混音 → QA。
- **注意**：60 秒口播 240–320 字；每段 ≤3 句；每 2–3 个抽象概念补一个具体例子。

### 5.3 产品发布 / 广告

- **工具**：huashu-motion。
- **流程**：收集真实素材（官网/截图/logo/产品图）→ 一句话定位 → 3 个方向 → treatment → 最难镜头 → 写谱/音效 → `om check`/`om qa` → 渲染。
- **注意**：logo 用真实文件，不重画；不伪造 UI/数据/用户评价；第三方素材写来源/许可。
- **示例 prompt**：

```text
用 huashu-motion 给我的产品做一支 30 秒发布片，官网是 <URL>。
先读产品，给我 3 个方向（每个 1 张真关键帧 + 1 张卡片），不要直接开做。
我选一个后，你写 treatment、先做最难镜头、om sound、om check、om qa、om render。
```

### 5.4 历史 / 纪录

- **工具**：lemo-opuscar（`city-symphony`、`visual-investigation`、`newsreel`、`archive-lighttable`、`ukiyoe`、`woodcut`）。
- **流程**：一手史料 → treatment → 素材授权清单 → 章节化生产 → contact sheet + 全片看。
- **注意**：传说不当史实；素材许可逐条记录；不要伪造档案。

### 5.5 新闻 / 数据

- **工具**：lemo-opuscar（`visual-investigation`、`news-package`、`dataviz`）；huashu（`data-story`）。
- **流程**：原始文件 → 事实/数字表 → 分镜 → 成片 → 法务/事实复核。
- **注意**：不做未经核实的指控；引用完整；不用别人的新闻画面冒充自己的素材。

### 5.6 竖屏 / 短视频

- **工具**：huashu（`kinetic-type`/`loop`）。
- **流程**：8 标题 + 5 钩子 → 成片 → 3:4/9:16 重排 → 封面 → 抖音母带。
- **注意**：首帧就是封面；主体占 60% 高；字幕在安全区；不要把 16:9 直接裁成 9:16。

### 5.7 视觉实验 / loop

- **工具**：huashu（`generative-field`、`continuous-morph`、`kinetic-type`）；Lemo（`swiss-motion`）。
- **流程**：一个母题 + 一个变形规则 → 5–15 秒 → 首帧=末帧 → `om qa --loop` → MP4/GIF/透明 MOV。
- **注意**：不要 10 个效果；不要 UI chrome 上加 glow/渐变；morph 容器里的文字要独立进出。

### 5.8 3D 产品 / 场景

- **工具**：huashu（`3d-object`，Three.js）；Lemo（`glass-product`、`lowpoly-island`）。
- **流程**：真实素材/产品图 → 3 方向（恰好一个 3D）→ treatment → 最难镜头 → QA。
- **注意**：3D 要有体量、材质、部件；不要几个方块冒充建模；首帧要能认出主体。

### 5.9 游戏 / 互动 demo

- **工具**：Lemo（`pixel-rpg`、`microgame`、`game-show`）；awesome 的 playable 案例。
- **流程**：一个挫败瞬间/机制 → 低多边形/像素/HUD → 5 秒重演 → 音效卡点 → QA。
- **注意**：不画现成 IP 角色/地图/枪械/Logo；不用未授权游戏音乐/语音。

### 5.10 儿童 / 绘本

- **工具**：Lemo（`crayon-book`、`paper-popup`、`watercolor`）；huashu（`art-styles`）。
- **流程**：简单故事（想要→遇到→解决）→ 角色设定 3–4 表情 → 大色块/粗轮廓 → 温暖配音 → QA 儿童可读性。
- **注意**：不出现惊吓/血腥/成人暗示；不伪造科学事实。

### 5.11 长片 / 纪录

- **工具**：Lemo（`edit-documentary`、`city-symphony`、`visual-investigation`）；PDoom 长 MV。
- **流程**：一章一个文件/agent → 共享 timeline 只读 → 素材授权清单 → TTS/ASR → 混音 → contact sheet + 0.2s 条 + 全片看。
- **注意**：长片不是「2 分钟片拉长」；章节化 + 并行 + 统一转场语法是前提。

## 6. 组合规则

### 6.1 必须组合的

| 组合 | 为什么 | 交接物 |
|---|---|---|
| `short-video-script` + 任意成片工具 | 它只出文案/分镜，不渲染 | 8 标题、5 钩子、口播稿、分镜表 |
| 调研工具 + 事实类赛道 | 历史/科学/医学边缘题必须读原文 | 来源清单、原文摘录、数字表 |
| Lemo 的 `DIRECTOR.md` + PDoom/Remotion | Lemo 给 treatment/分镜方法，PDoom/Remotion 给工程 | `TREATMENT.md`、`STORYBOARD.md` |
| 成片工具 + QA | 作者自评不算 | 抽帧、响度、问题清单 |
| 浏览器工具 + 人工发布门 | 可以填页/截图，不能代替用户审核 | 发布页截图、作品管理核对 |

### 6.2 不能混的

- **一个片子只用一个主运行时**：不要同时用 huashu 的 `index.html`、Lemo 的 `core/render`、Remotion。
- **一个片子只用一个主风格 + 一个辅助手法**：Lemo `city-symphony` + huashu `kinetic-type` 可以；三个风格库混用不行。
- **不要用两个一键成片工具抢同一期**：两个完整 timeline 会互相覆盖。
- **不要把图像生成当动画引擎**：它只出静帧；动画必须由代码/渲染器生成。
- **不要用浏览器工具渲染**：浏览器是调研/发布工具，不是帧渲染器。
- **不要用风格蒸馏搬内容**：只学画面语法，不搬文案、角色、镜头、配乐、品牌。

### 6.3 五条常用流水线

#### 流水线 1：音乐概念 MV（有歌，90–180 秒）

```text
歌 + 授权
  → 拆 BPM、段落、drop、歌词表
  → 写 TREATMENT.md
  → 写 STORYBOARD.md（Time / Lyric / Shot / Out）
  → PDoom 工程或 Remotion 实现
  → 混音 + 响度
  → 独立 agent 冷审 + 全片带声音看一遍
  → MP4 + SRT + 封面 + 授权清单
```

#### 流水线 2：音乐概念片（无歌，30–60 秒）

```text
概念/情绪/产品
  → huashu 3 个方向（每个 1 张真关键帧）
  → 选 1 个 → treatment + 节奏单
  → 先做最难镜头
  → om sound 写谱 + 音效
  → om check / om qa / 全片看一遍
  → om render → MP4 + GIF + share.md
```

#### 流水线 3：知识科普（30–138 秒，无口播）

```text
选题
  → 查一手资料
  → huashu（3b1b/kurzgesagt）或 Lemo（swiss-motion/dataviz）
  → 写 3 个结构 → treatment → 分镜
  → 5 秒测试 → 全片 → QA
```

#### 流水线 4：产品发布 / 品牌片（15–60 秒）

```text
产品资料/官网/真实素材
  → huashu om grab 收素材
  → 3 个方向 → 选 1 → treatment
  → 先做最难镜头 → om sound
  → om check / om qa
  → om render（可选 --blur）
```

#### 流水线 5：历史 / 纪录（3–20 分钟）

```text
史料原文
  → Lemo treatment（visual-investigation / newsreel / city-symphony）
  → 素材授权清单
  → 口播或字幕
  → 章节化生产（一章一个文件/agent）
  → 联系表 + 0.2s 条 + 全片看
```

## 附录 B：FAQ

**Q：Skill 和仓库有什么区别？**  
A：Skill 有 `SKILL.md`，agent 能直接读并执行；仓库可能只是源码、模板或语料库，需要你自己读/改。

**Q：Lemo 是不是 59 个 skill？**  
A：不是。Lemo 只有 1 个 skill；59 个是 `STYLE.md` 风格卡。

**Q：PDoomVideo 能直接出片吗？**  
A：能，但它是一个固定 156.6 秒 MV 的工程模板；要改成你的歌，需要改音频、BPM、歌词表、分镜和章节代码。

**Q：awesome / opus-video-prompts 能直接出片吗？**  
A：不能。它们是 prompt/案例语料库；要接 huashu/Lemo/PDoom/Remotion。

**Q：huashu 能拿我的歌做 MV 吗？**  
A：官方流程不是。它默认自己写谱；要用现成歌，需要手动接音频并自己保证卡点。要逐句歌词叙事，优先 PDoom/Remotion。

**Q：为什么 PDoom 不能直接抄？**  
A：仓库没有 LICENSE 文件，默认保留所有权利；`package.json` 的 ISC 是模板残留。只学方法，重写实现。

**Q：为什么 15/16 不是 Remotion？**  
A：它们的 `<build>` 第 1 条写 `One HTML file`；管线是 Playwright 截帧 + ffmpeg `tmix`。规则可迁移，但技术栈不是 Remotion。

**Q：35 种艺术风格在哪里？**  
A：它们在 `huashu-art-motion`（另一个项目），不在 huashu-motion 里；需要单独安装引擎，不能直接用 huashu-motion 跑。

**Q：没有授权音乐怎么办？**  
A：交无声母版 + cue sheet；不要从网上抓歌；只使用原创、已授权或用户确认有授权的曲子。

**Q：可以同时用两个成片工具吗？**  
A：不要。一个片子只用一个主运行时/主风格；支持类工具可以叠加。

**Q：多久能做完一支？**  
A：30–60 秒概念片：1–2 天；30–90 秒风格短片：2–5 天；90–180 秒 MV：3–10 天；取决于素材和修改轮数。
