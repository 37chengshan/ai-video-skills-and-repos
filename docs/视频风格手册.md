## 0. 怎么用这本手册

### 0.1 三分钟选型

1. **先定赛道**：你要做的是「一个机制解释一个现象」的知识片、产品片、历史片、音乐 MV，还是纯视觉实验？
2. **再定有没有口播**：无口播优先黑金 / 暗金 / 灯火 / 战术屏；有口播优先暖纸 / 像素贴纸 / Storytime。
3. **再定画幅和时长**：抖音主版 16:9、约 2:18；竖屏 3:4 或 9:16；产品片 30–60 秒；MV 90–180 秒。
4. **最后查风格卡**：先看 `styles/README.md`，再看对应目录的 `README.md` / `配方卡.md` / `预览.jpg`，不要凭记忆开工。

### 0.2 本手册的约定

- `<ENGINE>` = `/Users/cc/video/weilanx-claude-videos`
- `<期>` = 作品 ID，例如 `ep36-boxed-pigs`
- `<素材目录>` = `materials/<风格目录>/<编号-中文短题>/`
- `<成片目录>` = `out/<风格目录>/<编号-中文短题>/`
- 所有 `npm` / `npx` / `node` 命令前先执行：

```sh
export NODE_OPTIONS=--max-old-space-size=4096
```

- 路径不确定时用：

```sh
bash scripts/ep-dir.sh <期> materials
bash scripts/ep-dir.sh <期> out
```

### 0.3 大型任务先调研

任何大型任务（新风格、新赛道、新工具、新工作流）先做 GitHub 调研：

1. 搜 3–5 个同类仓库，读 README、LICENSE、目录结构、示范片。
2. 记录「可复用方法 / 不可复用内容 / 许可」。
3. 选 1 个主参考 + 1 个备选，不贪多。
4. 先做 5 秒测试，再决定是否投入整期。
5. 调研结论写进 `research/` 或本期素材目录，不要只留在聊天里。

不要从零造轮子；也不要因为「有仓库」就直接搬代码。先看许可，再看结构，最后重写。

### 0.4 三条不可违反的原则

1. **画面里的每个数字都要有出处**：论文读到摘要或原文、教材读到原段落、史料读到原文；能算的写成函数并在测试里复算；示意图标「示意」。
2. **不从别人的视频里提取 BGM**：配乐只用原创代码合成、已授权曲目或用户确认有授权的曲子；新曲子登记到 `public/music/README.md`。
3. **用户明确说「审核通过 / 可以发布」之前，不点发布**：生产自动化不等于发布授权。

### 1.2 赛道选择的四个判断

**判断一：这个题能不能画成一个模型？**

能画成「输入 → 规则 → 输出」的，优先知识动画；只能靠说的，优先口播或播客，不要硬做动画。

**判断二：观众有没有体感？**

反直觉选题 = 人人遇到过的处境 + 一个能画出来的机制 + 一个可查的一手出处。三者缺一，播放量会明显下降。

**判断三：你有没有一手资料？**

历史类必须读到原文；身体类优先原始论文；游戏类优先官方补丁说明 / 技术博客；没有资料就换题，不要用「据说」。

**判断四：你的产能撑不撑得住？**

- 黑金 / 灯火 / 暗金：一期 3–7 天，适合精品。
- 战术屏：一期 2–4 天，适合稳定周更。
- 像素贴纸 / 暖纸：一期 1–3 天，适合高频。
- 35 艺术风格实验片：1–2 天，适合做片头、预告、风格测试。
- MV：3–10 天，适合品牌、音乐人合作、账号升级。

### 1.3 不建议做的赛道

- 「十个冷知识」合集：没有单一机制，观众记不住，算法也不好打标签。
- 纯新闻复述：没有模型、没有出处、没有二次传播点。
- 纯技巧合集：分享率低，除非有「冤 → 翻案 → 招」的叙事。
- 医疗诊断 / 治疗 / 用药 / 疗效 / 营养建议：没有资质不碰。
- 搬运 / 二创别人视频的文案、画面、配乐：版权风险高，且账号无法建立风格。

## 2. 频道基线与硬规则

### 2.1 账号定位

- 一句话：**一期一个反直觉机制，解释一个你每天都会遇到的现象。**
- 栏目：数学 / 博弈 / 概率 / 经济；身体 / 生理 / 进化；心理 / 感知 / 认知；历史 / 制度；自然 / 物理 / 生物。
- 一期一个机制，2–3 分钟讲完，能画成一个可验证的模型或实验。
- 风格：黑金光影为旗舰，其他风格按赛道分工。
- 语言：中英双语同步；中文主版发抖音 / B站，英文版发 YouTube / X。

### 2.2 开头 0–5 秒

- 必须有精致 3D 建模、非匀速运镜、与重拍同步的音频。
- 2D 大字 / 淡入不算开头。
- 第 0 帧就要有巨大锚点和冲突：主体、动作、数字、问题，至少有一个。
- 禁止黑屏等字幕、Logo 动画、慢淡入。

**数据依据**：ep52《三门问题》播放 1216、2 秒跳出 41.4%、5 秒剩 26%、完播 0.33%。13 条对标的差距主要在主体大小、材质层次、场景变化、钩子和落回生活，不在配色。先把主体做大、把场景做出层次，再谈配色。

### 2.3 反直觉合集视觉模板

按 ep52《三门问题》的做法：

- 所有页面摆在一张大画布上（`PAGE` 一格 1920×1080）。
- 换场镜头在画布上上下左右滑动到下一页，不做无方向推进缩放。
- 结尾镜头拉远露出整张画布，所有页面加金框，压一句总结，再出下期问题。

### 2.4 固定结尾

- 最后 6–8 秒，镜头从最后一页拉远到整张画布（`scale ≈ 0.94 / 列数`）。
- 所有页面加金框，压一句总结。
- 出「下期 · 反直觉 NN」这一行，不能只有 `SparkTitle`。
- ep58 已按此执行，新一期不要各做各的结尾。

### 2.5 健康内容红线

- 身体类只讲生理机制、进化与感知。
- 不做疾病诊断 / 治疗 / 用药 / 疗效 / 营养建议。
- 不出现「致癌」「治愈」「最健康」这类结论。
- 身体数据标「示意」。

### 2.6 事实标准

| 类型 | 最低要求 | 画面标注 |
|---|---|---|
| 论文 | 读到摘要或原文；关键数字能复算 | 作者年份、期刊；示意标「示意」 |
| 教材 | 读到原段落 | 书名、版次、页码 |
| 史料 | 读到原文 | 书名、卷次、条目 |
| 官方博客 / 补丁 | 读到原文 | 厂商、文章名、年份 |
| 自己计算 | 写成函数 + 测试复算 | 「据公式计算」 |
| 传说 / 争议 | 标注「传说 / 学界争议」 | 不当作史实讲 |

### 2.7 版权与原创

- 对标视频只拆结构，不搬文案、画面、配乐。
- 不从别人的视频里提取 BGM。
- 配乐只用 `grid-noir`、`we-never`（已授权）或用户确认有授权的曲子。
- 新曲子在 `public/music/README.md` 登记来源、授权范围、BPM、时长、重拍。
- 版权角色重画为明显不同的原创角色；品牌 Logo、水印、作者名、肖像不搬。
- 参考视频和帧不进 git；拆解包放 `materials/00-公共/风格蒸馏/<风格ID>/<视频名>/`。

### 2.8 发布门

- 成片先通过主模型检查（测试、QA、响度、封面、文案事实）。
- 再由 **Codex GPT-6.1 Sol High** 与 **DeepSeek 4.1** 交叉审核。
- P0 全修，优化一轮后，把开头 5 秒 / 成片 / 封面 / 文案给用户看。
- **用户明确说通过才能发布。**
- 发布必须打开平台的 AI 内容声明。
- **不加定位 / 位置**，浏览器定位权限弹窗一律拒绝。
- 删除、隐藏作品，点赞、评论、私信、投抖加，先问用户；不批量注册账号，不刷互动，不靠注销重开来试探推荐机制。


- 有人声的期数导出 `stems/`（人声、配乐、音效）并重新混音限幅

```sh
cp "<成片目录>/<期>.mp4" "/Users/cc/video/成片/<合集>/<编号-中文题>/主片.mp4"
```

```sh

  "<素材目录>/封面-3x4.png" \
  --timeout=120000 --log=error
```

`<期>-cover-tall` 是黑金 / 多数风格的命名；其他风格按当期 `Root.tsx` 里注册的 composition ID 替换。

横版 16:9 和 4:3 按当期 `CoverWide` / `Cover` 组件渲染，或从成片抽帧后重新排版；不要直接拿视频截帧当封面。

这是黑金 `timeline.ts` 格式的字幕脚本；其他风格用对应 skill 的字幕脚本，或按 `CUES` 自己生成。产物：`字幕稿.md`、`字幕.srt`（中文一行 + 英文一行）。

### 4.2 黑金光影风

**定位**：讲博弈论、经济学、认知、冷知识、AI 原理这类「一个模型解释一种现象」的横屏 16:9 风格。像在暗房里做实验：近黑底、暖色烟雾、所有东西发光、金色粒子聚成标题、霓虹细线画收益矩阵和曲线、聚光灯打在发光小人身上、底部中英双语字幕。

**和暗金的区别**：暗金是「烛光下翻古籍」，偏历史；黑金是「暗房里做实验」，偏模型和数据。

**画面**：

### 7.2 Lemo：风格卡与导演流程

**规模**：`styles/` 59 个风格目录 + `_template`，11 类；默认 30–60 秒、1920×1080 / 24fps（`STYLE.md` 可覆盖）、−14 LUFS。

**最值得学**：

- `STYLE.md` 固定 11 节：本质与不是什么、材料与渲染、颜色逻辑、字体与字幕、运动质感、相机语法、声音调色板、原生动作、介质陷阱、引擎、变化空间。只写跨作品不变的风格规则；故事、分镜、时长、BPM、调性放 `DEMO.md`。
- 评价优先级：声音 → 节奏 → 镜头 → 导演。
- 城市交响：配乐先写、是脚本；切点踩拍或细分拍；机器快、人慢；一个脆弱主体慢下来；结尾重拍硬切黑。
- 视觉调查：档案、地图、时间线、证词，像调查记者。
- 新闻包装：巨字压素材、档案放映窗、实时倒计时。

**不能拿**：原片文案、画面、配乐、品牌、作者名。

**本地用法**：

1. 读 `styles/<风格>/STYLE.md` 和 `DEMO.md`。
2. 复制「结构」到自己的风格卡，不复制内容。
3. 用本地 Remotion 重写；不要直接把 Lemo 的代码搬进来。

### 7.3 PDoom：纯函数 MV 工程

**规模**：156.6 秒、1920×1080、16:9、24fps、3759 帧；9 章、62 镜、平均 2.5 秒/镜。

**技术栈**：p5.js 2.3.3 + p5.brush 2.2.3 + puppeteer-core 25.11.0；原生 JS，无 React；`createCanvas(W,H,WEBGL)`、`pixelDensity(1)`、`noLoop()`，再合成到 2D canvas。

**九章时间**：

| 章 | 时间 |
|---|---|
| `c01_lab` | 0–23 |
| `c02_chorus1` | 23–38.5 |
| `c03_takeoff` | 38.5–59 |
| `c04_chorus2` | 59–73 |
| `c05_obsolete` | 73–95.4 |
| `c06_chorus3` | 95.4–109.4 |
| `c07_scale` | 109.4–123.5 |
| `c08_chorus4` | 123.5–140.5 |
| `c09_finale` | 140.5–156.6 |

**工程契约**：

- `timeline.js:chapter(name,start,end,shots)` 注册章节。
- 镜头 `fn(t, lt, dur)` 必须绘制完整帧、是 `t` 的纯函数。
- 禁止跨帧状态和 `Math.random()`。
- 稳定随机用 `hash(i)`，手绘抖动用 `jit(a)`。
- `ANIMATION_GUIDE.md` 用于并行 subagent briefing。
- 每章一个文件，放在 PDoom 仓库的 `src/ch/`。

**最值得学**：把「音乐时间」变成「纯函数时间」；章节并行生产；水彩笔刷的分层和纸纹。

**水彩实现要点（可直接复用）**：

| 要点 | PDoom 做法 | 迁移到 Remotion |
|---|---|---|
| 上色 | `paint(pts,{wash})` 平涂角色；`fill/fillOp/bleed/tex/border` 画背景、光、阴影 | 预渲染 p5 帧，或用 SVG `feTurbulence` + 多层半透明 path 仿渗色 |
| 干刷 | `hatch:{d,a,o,b,c,w}`，刷子 `charcoal`/`HB`/`dry` | 纹理贴图 + 遮罩；别用 CSS noise 冒充纸纹 |
| 轮廓 | `ink/sw/br`；`ink:null` 去边；角色描边 0.8–1.6 | 手绘 path 描边，粗细随主体大小变 |
| 抖动 | `jit(a)` 每秒重播 12 次；`hash(i)` 稳定随机 | 每 2–3 帧换 seed，用对象 id 锁定随机 |
| 相机 | `camBegin/camEnd`；`shakeXY` 做打击 | `interpolate` + `transform`；shake 用阻尼正弦 |
| 节拍 | `pulse/pulse2`；`kf` + `backOut/elasticOut` | `spring` + `Easing.out(Easing.back)`；拍点先算帧号 |
| 字幕/音效 | `letter`/`sfx`；字幕带 y 975–1070，主体 y<960 | 字幕层 + `<Audio>`；把安全区写进组件 |
| 性能 | 目标 ≤2.5 秒/帧，绝不超 4 秒；少而大的形状 | 预计算 path；避免每帧几百个 filter |

PDoom 用 p5.brush，不是 Remotion；Remotion 里要么预渲染 p5 帧，要么用 SVG/Canvas 仿。不要直接把 p5 的 `paint()` 代码搬进 React 组件。

**不能拿**：原曲、原词、原图；代码是 ISC，但素材授权未确认。

### 8.5 生产纪律

## 9. 无口播 SOP（2:18 知识片）

适用：黑金、暗金、灯火、战术屏。下面以黑金为主，其他风格替换组件和文案规则。

### 9.1 十步流程

| 步 | 做什么 | 产物 |
|---|---|---|
| 0 | 选题 / 期号 | 标题、钩子、事实边界、可视化方向 |
| 1 | 查一手资料 | 来源清单、关键数字、原文摘录 |
| 2 | 定锚词 | 2–4 字，能贯穿全片、结尾能重新定义 |
| 3 | 写文案与卡点 | `文案与卡点.md`：拍号、字幕、画面、音效 |
| 4 | 写 `timeline.ts` | 全片唯一时间表 |
| 5 | 音频 | 配乐 + 音效 + 混音 |
| 6 | 画面 | 组件复用 + 本期专属设计 |
| 7 | 注册 / 测试 | `Root.tsx`、测试全绿 |
| 8 | 自查 | `qa.mjs` 抽帧 + 响度 + 音效 |
| 9 | 导出 / 交付 | mp4、封面、文案、字幕 |
| 10 | 发布 | 填页、截图、等用户审核 |

### 9.2 第 0 步：选题

好选题 = 人人有过的处境 + 能画出来的模型 + 可查一手出处。

标题：

- 第二人称、痛点、问句。
- 战术屏 ≤ 12 字；黑金可以稍长，但标题卡不能折行。
- 答案不能是观众一眼猜得到的。
- 先写 8 个候选，再选 1 个；发布文案保留候选和最终选择。

钩子：

- 12–25 个汉字，最多 2 句。
- 先冲突后机制。
- 第 0 帧就要有主体、动作或大字。

### 9.3 第 1 步：查资料

- 只认原文：论文、教材、史料、官方博客 / 补丁说明。
- 每个数字、每句原话写进 `timeline.ts` 常量，测试里断言。
- 至少 2 个独立来源，其中至少 1 个同行评审或官方原文。
- 只读到摘要的细节，字幕里不要说得比摘要更具体；发布文案内部核对清单注明「据正文，未读到」。
- 能自己算的就自己算，测试里复算。

### 9.4 第 2 步：定锚词

- 2–4 个字，一个词装下整期原理。
- 第一次出现在第 1 章结尾（青色），第 48 小节砸出，情绪翻转句里再出现一次。
- 例：过去、对称、公平、坑队友、自动驾驶、一点点、巧合、过期、奇迹、一别两宽、银碗、交子、冬天。

### 9.5 第 3 步：写 `文案与卡点.md`

模板：

```markdown
# <期> 文案与卡点

## 基本
- 标题：
- 副标题 / 英文：
- 锚词：
- 时长 / 拍号：
- 配乐：
- 来源：

## 章节
| 章节 | 拍号 | 时间 | 内容 | 画面 | 音效 |
|---|---|---|---|---|---|

## 字幕
| 拍号 | 中文 | English | 备注 |
|---|---|---|---|

## 事实
| 数字 | 来源 | 原文 | 测试 |
|---|---|---|---|

## 自查
- [ ] 每个数字有出处
- [ ] 示意图已标「示意」
- [ ] 没有医疗结论
- [ ] 没有搬运
```

### 9.6 第 4 步：写 `timeline.ts`

硬规则：

- `CUES` 每句挂拍点；`null` 行同一行写 `// 说明`。
- 只有 `HALF_BEATS` 里的两句能以「——」结尾。
- `SHOTS` 首尾相接，最后一个是 `ask: [fb(59), DURATION]`。
- 每个章节起点都是某个镜头的起点。
- 画面元素的出场帧必须在所在镜头时间范围内。
- `timeline.ts` 不能 import 其他 `.ts` / `.tsx`。
- 需要素材库里的纯函数就在 `timeline.ts` 里自己写一份。

骨架：

```ts
  [0, '……', '……'],

  // ...
] as const;

  ['hook', 0, 24],
  // ...
] as const;
```

### 9.8 第 6 步：画面

- `npm run typecheck && npm test` 全绿才继续。

### 9.10 第 8 步：自查

- 元素压到字幕区（y>860）。
- 示意图空间关系。
- 整片约 −15.5 LUFS、真峰值 ≤ −1.0 dBFS。
- 冲击类音效有没有被配乐盖住。

## 10. 口播 SOP（3–4 分钟）

适用：暖纸、像素贴纸、Vox、Storytime。以暖纸为例。

### 10.1 十步流程

| 步 | 做什么 | 产物 |
|---|---|---|
| 0 | 选题 / 标题 / 钩子 | 8 个标题、5 个 3 秒钩子 |
| 1 | 写口播稿 | 逐字稿，短句为主 |
| 2 | 录音 | 干声、无噪声、44.1kHz / 48kHz |
| 3 | 对齐 | 逐句时间、停顿、重音 |
| 4 | 写场景表 | 一句字幕一个画面变化 |
| 5 | 画面 | `DeskShow` / `Show` / Vox 组件 |
| 6 | 混音 | 人声、配乐、音效、ducking |
| 7 | 字幕 | 中文 + 英文 |
| 8 | 测试 / 自查 | 抽帧、响度、口型 / 对齐 |
| 9 | 导出 / 交付 | mp4、封面、文案、字幕 |

### 10.2 口播稿

- 短句（≤15 字为主）。
- 先冲突后机制。
- 每 3–5 句一个画面变化。
- 结尾一句强记忆点 + 自测问题。
- 不要把书面语直接念；念一遍，改掉拗口的地方。

### 10.3 录音

- 安静房间、近距离、避免爆音。
- 采样率 48kHz，24bit。
- 保留 3–5 秒环境声，方便降噪。
- 不要用背景音乐录。

### 10.4 场景表

| 时间 | 口播 | 画面 | 字幕 | 音效 |
|---|---|---|---|---|
| 0–3s | 钩子 | 大标题 + 主体 | 中文 + 英文 | impact |
| 3–8s | 冲突 | 对比 / 反例 | 中文 + 英文 | whoosh |
| ... | ... | ... | ... | ... |

### 10.5 混音

- 人声约 −16 至 −19 LUFS（以当期实测为准）。
- 配乐约 −34 LUFS，有人声时自动 ducking。
- 音效不盖人声；关键句留白。
- 整片真峰值 ≤ −1 dBFS。
- 导出 stems：人声、配乐、音效。

### 10.6 字幕

- 中文一行，英文一行。
- 每句 ≤ 24 字（中文）。
- 专有名词保留原文；首次出现可加中文解释。
- 不要用机器翻译直接交付；至少人工过一遍。

### 10.7 口播常见问题

| 问题 | 原因 | 修法 |
|---|---|---|
| 像念稿 | 书面语、句子太长 | 改短句、加停顿、加反问 |
| 节奏平 | 没有重音 | 每段一个重音，画面跟着重音变 |
| 信息密 | 一句多个概念 | 一句一个概念，拆镜头 |
| 出戏 | 画面和口播不对应 | 按口播重写场景表 |
| 声音闷 | 麦克风太远 / 房间反射 | 近讲、加吸音、降噪 |
| 配乐盖人声 | 没有 ducking | 侧链压缩 / 手动自动化 |

## 11. 音乐概念 MV 教程

这一章是新增重点：给一支音乐做「概念 MV」，不是给知识片配一首歌。

### 11.1 什么是概念 MV

**概念 MV**：音乐是脚本，画面是音乐的可视化论证或叙事；没有口播；一个视觉母题贯穿；90–180 秒；观众听完歌，记住一个画面。

**不是什么**：

- 不是「把知识片配乐」：知识片的结构是论证，MV 的结构是音乐。
- 不是「歌词字幕 + 风景空镜」：那是卡拉 OK / 旅行视频。
- 不是「表演 MV」：除非你明确要拍人声表演；概念 MV 的主角是视觉母题。
- 不是「十个炫技镜头合集」：没有母题，观众记不住。

**和知识片的区别**：

| 维度 | 知识片 | 概念 MV |
|---|---|---|
| 结构来源 | 论证 / 章节 | 音乐 / 段落 / 重拍 |
| 主角 | 模型 / 概念 | 视觉母题 |
| 口播 | 有或无 | 无 |
| 时长 | 2–3 分钟 | 90–180 秒 |
| 节奏 | 信息密度 | 音乐能量 |
| 结尾 | 结论 / 下期问题 | 回到开头，但变了 |
| 成功标准 | 讲清楚 | 记住了画面 / 情绪 |

### 11.2 第一步：选曲与授权

**优先级**：

1. 原创 / 委托创作：版权最清楚，可以拿到 stems。
2. 已授权曲库：确认平台、期限、地域、商业化、二次剪辑、Content ID。
3. 用户确认有授权的曲子。
4. 不做：从抖音 / B站 / YouTube / 别人的视频里提取 BGM。

**需要拿到**：

- 音频文件：WAV / 高质量 MP3。
- BPM、拍号、时长。
- 段落标记：intro / verse / chorus / bridge / outro。
- 重拍 / 停顿 / 硬切点。
- stems（人声、鼓、贝斯、旋律、氛围）如果可用。
- 授权范围：平台、地域、期限、商业化、改编、署名。
- 是否注册 Content ID；如果会，发布时可能被识别，提前处理。

**登记**：`public/music/README.md` 写清楚来源、作者、授权、BPM、时长、重拍、是否可商用、是否随仓库分发。

### 11.3 第二步：听歌拆结构

**工具**：

```sh
# 测 BPM / 小节 / 重拍（本地脚本）
uv run --with numpy python \
  .claude/skills/weilanx-creator-gilded-video/scripts/beats.py \
  public/music/<曲子>.mp3 --to 40
```

也可以用 Audition / Logic / Ableton / Sonic Visualiser 看波形和频谱。

**要标出来的**：

| 项目 | 说明 |
|---|---|
| 起始偏移 | 第 1 拍在几分几秒；有没有前奏噪声 |
| BPM | 自动测完要手动核对，防止半速 / 双速 |
| 拍号 | 4/4、3/4、6/8；大多数流行 / 电子是 4/4 |
| 小节 | 每小节几拍；重拍在第几拍 |
| 段落 | intro / build / drop / breakdown / final / outro |
| 能量 | 低 / 中 / 高；在哪里上升、下降、停顿 |
| 音色 | 鼓、贝斯、合成器、人声、环境声 |
| 硬切点 | 停顿、reverse cymbal、impact、silence |
| 结尾 | 渐弱、硬停、回到主和弦、loop 点 |

**Cue Sheet 模板**：

```markdown
| 时间 | 小节 | 拍 | 段落 | 能量 | 音乐事件 | 画面事件 |
|---|---|---|---|---|---|---|
| 0:00 | 1 | 1 | intro | 低 | 环境垫 | 一个物体在黑暗里 |
| 0:08 | 5 | 1 | intro | 低 | 鼓点进入 | 物体开始发光 |
| 0:16 | 9 | 1 | build | 中 | 贝斯进入 | 镜头开始推进 |
| 0:32 | 17 | 1 | drop | 高 | 重拍 | 主体炸开 / 硬切 |
```

**规则**：

- 不要只信自动 BPM；用脚打拍子核对。
- 不要把所有镜头都卡在重拍；细分拍也要用。
- 先标「必须发生」的 5–8 个音乐事件，再填画面。
- 音乐稀疏的地方，镜头可以长；音乐密的地方，切得短。

### 11.4 第三步：写概念

**一句话 logline**：

> 这支 MV 用 [视觉母题] 经历 [音乐情绪 / 概念]，最后回到 [开头画面]，但 [变化]。

例：

- 用「一座城市的一天」经历「从秩序到失控再回到秩序」。
- 用「一只发光猪的猪圈」经历「重复博弈从背叛到合作」。
- 用「一扇门的光」经历「概率从 1/3 变成 2/3」。

**3–5 个母题**：

| 母题 | 视觉规则 | 出现位置 |
|---|---|---|
| 门 | 每扇门一根光柱，高度 = 概率 | 开头、转折、结尾 |
| 光 | 青 = 合作，红 = 背叛 | 全片 |
| 表盘 | 每拍点亮一格 | 回落段 |
| 手 | 只在关键句出现 | 副歌 |

**颜色脚本**：

- 4–6 个颜色，一个主色，一个强调色。
- 颜色要有语义，不要只是「好看」。
- 开头和结尾用同一组颜色，但强调色可以换。

**结尾**：

- 回到开头画面，但有一个变量变了。
- 不要用「淡出 + logo」；用音乐的最后一下。

### 11.5 第四步：结构模板

#### 90 秒（120 BPM，45 小节，180 拍）

| 段落 | 小节 | 时间 | 拍 | 画面 |
|---|---|---|---|---|
| Intro | 1–8 | 0:00–0:16 | 1–32 | 建立母题，慢推，一个主体 |
| Build | 9–20 | 0:16–0:40 | 33–80 | 规则出现，切点变密 |
| Drop | 21–32 | 0:40–1:04 | 81–128 | 最大对比，硬拍，主体变化 |
| Breakdown | 33–38 | 1:04–1:16 | 129–152 | 抽掉一层，慢下来，脆弱时刻 |
| Final | 39–44 | 1:16–1:28 | 153–176 | 回到主 motif，加速 |
| Coda | 45 | 1:28–1:30 | 177–180 | 最后一击，硬切黑 |

#### 2:18（112.5 BPM，256 拍 + 1 秒）

| 段落 | 拍 | 时间 | 画面 |
|---|---|---|---|
| Hook | 0–24 | 0:00–0:13 | 巨大主体 / 冲突 / 问题 |
| Establish | 24–96 | 0:13–0:51 | 建立世界、规则、母题 |
| Develop | 96–160 | 0:51–1:25 | 变奏、对比、第二次出现 |
| Climax | 160–188 | 1:25–1:40 | 11 下硬拍，每拍一个动作 |
| Resolve | 188–224 | 1:40–1:59 | 回到母题，结论 / 情绪 |
| Redefine | 224–240 | 1:59–2:08 | 重新定义锚词 / 留下记忆点 |
| Outro | 240–256 | 2:08–2:17.5 | 拉远、留白、下期 / 署名 |

#### 3 分钟（120 BPM，90 小节，360 拍）

| 段落 | 小节 | 时间 | 画面 |
|---|---|---|---|
| Intro | 1–8 | 0:00–0:16 | 世界建立 |
| Verse | 9–24 | 0:16–0:48 | 规则 / 角色 |
| Chorus 1 | 25–40 | 0:48–1:20 | 第一次爆发 |
| Bridge | 41–48 | 1:20–1:36 | 抽离 / 变奏 |
| Chorus 2 | 49–72 | 1:36–2:24 | 最大能量 |
| Outro | 73–90 | 2:24–3:00 | 回到开头，结束 |

### 11.6 第五步：分镜 / 节拍表

**表头**：

```markdown
| # | 章节 | 时间 | 拍号 | 音乐事件 | 画面事件 | 主体 | 镜头 | 转场 | 文字 | 音效 |
|---|---|---|---|---|---|---|---|---|---|---|
```

**规则**：

- 一个镜头只发生一件事。
- 切点优先落在拍 / 细分拍；不要每刀都卡重拍。
- 音乐稀疏 → 长镜头；音乐密 → 短镜头。
- 重拍 → 硬切 / 闪光 / 主体变化 / 颜色反转。
- 停顿 → 静止 / 黑场 / 留白。
- 结尾 → 回到开头构图，但变量变了。
- 文字克制：只留标题、数字、出处、一句公版文本。
- 不要下三分之一人名、页眉、居中标题卡翻页、logo sting（除非风格明确需要）。

**8 镜示例（16 秒 intro，120 BPM）**：

| # | 时间 | 拍 | 音乐 | 画面 | 镜头 |
|---|---|---|---|---|---|
| 1 | 0:00 | 1 | 环境垫 | 黑暗里一个物体 | 固定 |
| 2 | 0:02 | 5 | 低频进入 | 物体表面亮起一条线 | 慢推 |
| 3 | 0:04 | 9 | 鼓点 | 线扩展成轮廓 | 侧移 |

### 11.8 第七步：工程实现

**本地 Remotion 结构**：

```text
src/episodes/<期>/
├── timeline.ts       # 拍号、镜头、字幕、事实常量
├── <期>.tsx          # 主 Composition
├── scenes.tsx        # 场景组件
├── CoverTall.tsx     # 3:4 封面
└── CoverWide.tsx     # 16:9 封面
```

**主 Composition 骨架**：

```tsx
import React from 'react';
import {AbsoluteFill, Audio, Sequence, staticFile} from 'remotion';
import {SHOTS, DURATION, FPS} from './timeline';

export const MyMV: React.FC = () => {
  return (
    <AbsoluteFill style={{backgroundColor: '#050302'}}>
      <Audio src={staticFile('music/track.wav')} />
      {Object.entries(SHOTS).map(([id, [from, to]]) => (
        <Sequence key={id} from={from} durationInFrames={to - from} name={id}>
          <Scene id={id} duration={to - from} />
        </Sequence>
      ))}
    </AbsoluteFill>
  );
};
```

示意代码；实际项目把 `SHOTS` 写成 `Record<string, readonly [number, number]>`，避免 `noUncheckedIndexedAccess` 下 `to - from` 报错。

**时间轴原则**：

- 所有动画是 `useCurrentFrame()` 的纯函数。
- 不用 `useState` 驱动画面；不用 `Math.random()`。
- 需要随机用 `random(seed)`（Remotion 提供，确定性）。
- 需要弹簧用 `spring({frame, fps, config})`。
- 需要插值用 `interpolate(frame, [a, b], [c, d], {extrapolateLeft: 'clamp', extrapolateRight: 'clamp'})`。
- 音频用 `<Audio>`；音效也可以 `<Audio>` + `startFrom` / `volume`。
- 不要用 CSS transition / animation；渲染时不可控。

**镜头组件**：

```tsx
const Scene: React.FC<{id: string; duration: number}> = ({id, duration}) => {
  const frame = useCurrentFrame();
  const t = frame / duration;
  // 只依赖 frame / t / duration，不依赖外部状态
  return <AbsoluteFill>{/* ... */}</AbsoluteFill>;
};
```

**节拍辅助**：

```ts
export const BPM = 112.5;
export const BEAT = 60 / BPM;
export const BAR = BEAT * 4;
export const fb = (beat: number) => Math.round(beat * BEAT * FPS);
```

**渲染静帧**：

```sh
npx remotion still src/index.ts <期> /tmp/<期>-f$(printf '%04d' $FRAME).png \
  --frame=$FRAME --scale=0.5 --timeout=120000
```

**注册**：

```tsx
<Composition
  id="<期>"
  component={MyMV}
  durationInFrames={DURATION}
  fps={FPS}
  width={1920}
  height={1080}
/>
```

**测试**：

- 片长 = `DURATION`。
- 每个镜头首尾相接。
- 关键拍号 ±2 帧。
- 音频文件存在。
- 事实常量与原文一致。
- 首帧 / 末帧非黑（除非设计如此）。

### 11.9 第八步：声音设计

**层次**：

| 层 | 作用 | 音量建议 |
|---|---|---|
| 音乐 | 主情绪 / 结构 | −16 LUFS 床 |
| 低频 impact | 重拍 / 转折 | 0.4–0.7 |
| riser | 进入爆点前 | 0.55–0.6 |
| whoosh | 转场 | 0.22–0.3 |
| foley | 动作 | 0.3–0.6 |
| 环境 | 空间感 | 0.1–0.2 |
| 静音 | 对比 / 留白 | 0 |

**规则**：

- 不要每个重拍都堆 impact；3–5 个关键点就够。
- 爆点前留 0.5–1 秒静音 / 收暗，爆点才有力量。
- 结尾硬停比渐弱更有记忆点（除非音乐本身是渐弱）。
- 人声 / 采样如果出现在音乐里，画面要给它一个「来源」。
- 混音时先听手机外放，再听耳机；短视频平台大多数是手机外放。

**响度**：

- 无口播：音乐床 −16 LUFS；整片约 −15.5 LUFS；真峰值 ≤ −1 dBFS。
- 抖音发布母带：约 −11 LUFS（以当期实测和平台为准）；不要盲目压到 0 dBFS。
- 有口播：音乐 −34 LUFS 左右，人声 −16 至 −19 LUFS。

**测量**：

```sh
ffmpeg -nostats -i "<文件>" -af ebur128=peak=true -f null - 2>&1 | tail -30
```

### 11.12 五个可复制的 MV 方案

#### 方案 A：城市交响（Lemo）

- 音乐：城市氛围 / 电子 / 爵士。
- 画面：同一座城市从清晨到深夜；建筑、车流、人群、地铁。
- 规则：机器快、人慢；一个脆弱主体慢下来；切点踩拍。
- 结构：建立 → 加速 → 高潮 → 硬停 → 再加速 → 硬停 → 安静尾声。
- 结尾：重拍硬切黑，留一句城市名 / 日期。
- 适合：品牌片、城市宣传、专辑先行曲。

#### 方案 B：机制水彩（PDoom）

- 音乐：钢琴 / 弦乐 / 氛围电子。
- 画面：一个概念变成一个水彩世界；9 章，每章一个场景。
- 规则：纯函数时间轴；章节并行；水彩分层 + 纸纹 + 渗色。
- 结构：实验室 → 副歌 → 起飞 → 副歌 → 过时 → 副歌 → 尺度 → 副歌 → 终章。
- 结尾：回到实验室，主体变了。
- 适合：科技 / 科学 / AI 主题 MV。

#### 方案 C：黑金反直觉（本地）

- 音乐：`we-never` / `grid-noir`。
- 画面：一个舞台贯穿；金线、青红语义色、发光小人。
- 规则：256 拍 + 1 秒；两个重拍；11 下硬拍；每拍一个动作。
- 结构：钩子 → 建立 → 推导 → 回落 → 结论 → 重新定义。
- 结尾：拉远 / 下期问题。
- 适合：知识号升级、反直觉合集、品牌合作。

#### 方案 D：UI morph loop（opus 15）

- 音乐：120 BPM，7 小节。
- 画面：一个 UI 元素 morph 成另一个；每个 beat 有事发生。
- 规则：1440×1440；纯 `seek(t)`；闭式弹簧；首帧 = 末帧。
- 结构：A → B → C → D → A。
- 结尾：无缝循环。
- 适合：产品发布、社交媒体 loop、品牌动效。

#### 方案 E：档案拼贴（Lemo / Vox）

- 音乐：爵士 / 氛围 / 电子。
- 画面：剪报、照片、文件、地图、时间线。
- 规则：元素 12fps；相机像调查记者；不伪造档案。
- 结构：问题 → 档案 → 矛盾 → 真相 → 回望。
- 结尾：回到第一张档案，标出之前没注意的细节。
- 适合：历史 / 新闻 / 调查类 MV。

### 12.2 卡点公式

```ts
export const BPM = 112.5;
export const BEAT = 60 / BPM;
export const BAR = BEAT * 4;
export const fb = (beat: number) => Math.round(beat * BEAT * FPS);
export const fr = (sec: number) => Math.round(sec * FPS);

export const HIT = fb(8);
export const HIT2 = fb(48);
export const DURATION = fr(BEAT * 256 + 1);
```

**规则**：

- 重拍前 0.75 秒收暗。
- 重拍前 3 帧静止。
- 重拍 +2 帧亮。
- 每小节第一拍轻推 1.2%。
- 两个大重拍推 4%。

### 12.3 字幕

**格式**：

- 中文一行，英文一行。
- 中文 ≤ 24 字 / 句（战术屏）；黑金可稍长，但不要超过两行。
- 英文不要直译到失去节奏；可以意译，但要保留数字和专有名词。
- 关键词用颜色标记：黑金青 / 红，战术屏 `【】` 青 / `〖〗` 红 / `〔〕` 橙，灯火 `【】` 蓝 / `〖〗` 红 / `〔〕` 金。
- 字幕不压主体；y≈910–930。
- 换句时旧句先淡到 25%，不要硬切。

**生成**：

```sh
node .claude/skills/weilanx-creator-blackgold-video/scripts/subtitles.mjs <期> "<素材目录>"
```

**检查**：

- 数字、年份、人名、书名、英文拼写。
- 断句是否自然。
- 中英文是否同步。
- 是否有错别字 / 多字 / 漏字。

### 12.4 封面

**三件套**：

| 封面 | 尺寸 | 用途 |
|---|---|---|
| 16:9 | 1920×1080 | YouTube、B站、横版信息流 |
| 4:3 | 1440×1080 | 部分平台横版 |
| 3:4 | 1080×1440 | 抖音、竖版信息流 |

**规则**：

- 不是黑图，不是视频截帧。
- 主体大、对比强、3 秒能看懂。
- 标题 ≤ 12 字（战术屏）；黑金可以稍长，但不要超过两行。
- 数字要大，来源要小。
- 不要放二维码、微信号、外部链接。
- 不要放未经授权的品牌 Logo、明星肖像。
- AI 生成封面要打开平台 AI 声明。

**渲染**：

```sh
npx remotion still src/index.ts <期>-cover-tall \
  "<素材目录>/封面-3x4.png" \
  --timeout=120000 --log=error
```

### 12.5 响度

| 场景 | 目标 | 真峰值 |
|---|---|---|
| 黑金 / 暗金 / 灯火 / 战术屏 | 整片约 −15.5 LUFS；音乐床 −16 LUFS | ≤ −1 dBFS |
| 抖音发布母带 | 约 −11 LUFS | ≤ −1 dBFS |
| 有口播 | 人声 −16 至 −19 LUFS；音乐 −34 LUFS | ≤ −1 dBFS |
| 纯音乐 MV | 音乐床 −16 LUFS；整片按平台 | ≤ −1 dBFS |

**注意**：`zhenlv-video` 写「抖音响度约 −11 LUFS，无口播期约 −16 LUFS」，黑金规格写「配乐床 −16 LUFS、整片约 −15.5 LUFS」。两者是「引擎默认」和「平台母带」的关系，不要混写。导出前用 `ebur128` 实测，按平台要求决定最终母带。

```sh
  "<期>-douyin.mp4"
```

先测再压；不要盲目压到 0 dBFS。

## 13. QA 清单与发布

### 13.1 五轮审查

| 轮 | 审什么 | 证据 |
|---|---|---|
| 1 | 事实与边界 | 来源、原文、测试、示意标注 |
| 2 | 文案与节奏 | 标题、钩子、字幕、时长、卡点 |
| 3 | 画面与镜头 | 抽帧、构图、可读性、遮挡 |

| 5 | 发布前 | 标题、正文、话题、封面、合集、声明、位置、时间 |

### 13.2 90 分制

| 维度 | 分值 | 检查 |
|---|---:|---|
| 事实 | 25 | 每个数字有出处；没有过度推断；示意标注 |
| 文案 | 20 | 标题、钩子、短句、结尾记忆点 |
| 节奏 | 20 | 前 3 秒、镜头长度、卡点、留白 |
| 画面 | 20 | 主体、材质、构图、文字、遮挡 |
| 声音 | 15 | 配乐、音效、响度、真峰值 |

低于 90 分退回修改，不发布。

### 13.3 P0 / P1

**P0（必须修）**：

- 事实错误 / 无出处。
- 医疗结论 / 诊断 / 治疗 / 用药建议。
- 版权素材 / 品牌 Logo / 水印。
- 黑帧 / 音画不同步 / 字幕错位。
- 封面是黑图 / 视频截帧。
- 发布页信息错误。

**P1（优化一轮）**：

- 字幕太长 / 折行。
- 主体太小 / 被遮挡。
- 节奏拖沓 / 镜头太长。
- 音效盖人声 / 配乐太响。
- 封面标题不够醒目。

### 13.4 发布前核对

1. 先读当期 `发布文案.md` 和 `审片.md`，逐项对照；不要凭记忆发。
2. 抖音标题以 `vibe知识大赏｜` 开头，正文必带 `#vibe知识大赏 #AI新星`。
3. **话题一个一个选**：在 `#添加话题` / 话题搜索里逐个选中；不要把 `#a #b #c` 整段粘贴进正文。
4. 封面三件套：16:9、4:3、3:4 都存在，都不是黑图、不是视频截帧。
5. 合集已选；自主声明 =「内容由 AI 生成」；位置为空；谁可以看 = 公开。
6. 用户没说立即发时，默认「定时发布」，不点「立即发布」。
7. 把标题、正文、逐个选好的话题、三张封面、合集、声明、位置、时间全部填好，保存发布页截图。
8. **停在发布页，等用户明确说「审核通过 / 可以发布」。**
9. 用户确认后只点一次「发布」。
10. 发布后到作品管理核对标题、封面、合集、发布时间。
11. **禁止重复点发布**；重复提交会生成重复作品。
12. 发错先停手问，不自行删除已发布作品；保留截图、时间、播放数据。

### 13.5 平台规格

| 平台 | 版本 | 画幅 | 备注 |
|---|---|---|---|
| 抖音 | 中文主版 | 16:9 成片 + 16:9 / 4:3 / 3:4 封面 | 打开 AI 内容声明 |

## 附录 C：常见问题

**Q：没有一手资料，能不能先做？**  
A：不能。先换题，或把范围缩小到有出处的部分。没有出处的数字不要上画面。

**Q：可不可以用别人的 BGM？**  
A：不可以。只用原创、已授权、用户确认有授权的曲子；新曲子登记到 `public/music/README.md`。

**Q：可不可以用参考片的画面做「致敬」？**  
A：不可以直接搬。只拆结构、节奏、配色方法；具体画面、角色、文案、品牌要重做。

**Q：封面可以直接从成片截一帧吗？**  
A：不建议。封面要重新排版：主体更大、标题更大、对比更强；截帧通常信息太碎。

**Q：发布页话题可以整段粘贴吗？**  
A：不可以。必须一个一个选；粘贴的井号平台不识别。

**Q：用户没说发布时间怎么办？**  
A：默认「定时发布」，不点「立即发布」；等用户明确说。

**Q：发错了怎么办？**  
A：先停手问，不自行删除；保留截图、时间、播放数据，再处理。

**Q：数据不好要不要马上换风格？**  
A：不要。看 5 条以上的趋势；单条数据受选题、发布时间、封面影响很大。

**Q：MV 一定要 2:18 吗？**  
A：不一定。90 秒、2:18、3 分钟都可以；关键是音乐结构和画面结构对齐。

**Q：没有 stems 能做 MV 吗？**  
A：可以。用整轨 + 音效设计；但画面切点要更依赖波形和段落标记。

**Q：35 种艺术风格能直接商用到客户项目吗？**  
A：先看上游许可（MIT）和素材来源；风格可以学，具体作品、角色、品牌不能搬。商业项目建议重做资产。
